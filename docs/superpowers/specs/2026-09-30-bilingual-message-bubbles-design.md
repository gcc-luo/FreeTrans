# 双语消息气泡设计

## 目标

修复 WhatsApp 翻译没有生效的问题，并让收发消息都在同一个聊天气泡中保留原文和译文。用户已确认发送与接收消息均需要双语显示。

## 用户体验

- 用户语言为中文、对方语言为英语时，发送中文消息前先翻译为英文。
- 对方收到英文消息。发送者本机的同一气泡显示英文译文在上、中文原文在下。
- 收到的英文消息保留原文，并在同一气泡显示中文译文；英文原文在上、中文译文在下。
- 同一消息重复扫描或界面更新时，译文和原文各显示一次。
- 翻译失败时显示可辨认的失败状态，不将未翻译文本误报为已翻译消息。

## 实现范围与数据流

- 聚焦用户报告的 WhatsApp 服务，同时保留 Google Chat 已有双语显示行为。
- 沿现有 WhatsApp WebView 拦截器检查输入事件、翻译请求、发送和消息气泡 DOM 更新四个环节，修复导致“没有反应”或只出现原文的断点。
- 外发消息继续在发送前翻译，消息服务只接收译文；本地气泡在消息出现后附加源文本。
- 入站消息维持服务原始文本，在其气泡内附加翻译文本。
- 译文和原文作为本地 DOM 展示状态，不改变聊天服务实际接收的入站内容，也不额外发送消息。
- 保持现有每个服务的语言和收发开关设置。

## 失败处理

- 找不到输入框、无法触发拦截、请求超时、翻译服务报错或气泡未能匹配时，记录不含完整消息内容的诊断信息。
- 外发翻译失败时保留输入内容并显示失败提示，用户可以重试或自行发送。
- 入站翻译失败时保留原始消息，不插入空白或重复译文。

## 验收标准

1. WhatsApp 中开启收发翻译后，输入一条中文并发送，接收方收到英文；发送者本机气泡同时显示英文和中文原文。
2. 收到一条英文消息后，原英文仍可见，气泡内同时显示中文译文。
3. 关闭任一方向的开关后，对应方向不再插入译文；另一方向保持工作。
4. 翻译请求失败时，界面给出可见反馈，消息文本不会静默丢失或被误标为翻译成功。
5. 对话更新或重复扫描后，每条消息仍只包含一份原文和一份译文。

## 验证方式

按手动验收标准在桌面端 WhatsApp 配方中检查方向设置、收发结果、重复扫描和失败反馈。此次实现按工作区规则不新增或运行自动化测试。
